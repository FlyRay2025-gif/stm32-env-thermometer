# 基于单片机的环境温度测量仪 —— 实验方案与实施（实施版）

**项目名称：基于单片机的环境温度测量仪设计与制作**
**项目性质：校级开放性实验室项目（2026-09-01 ～ 2026-11-01）**
**成果形式：实物作品 + 结题报告**
**文档版本：V1.1（2026-10-10 按实际实施情况修订）｜本公开版已脱敏、仅保留技术内容**

*项目主要内容：为解决传统温度测量响应迟缓、精度不足等弊端，设计以32系列单片机为核心控制器，结合DS18B20、LM35等温度传感器及液晶显示、报警、按键设置等模块，通过C语言编写程序并优化数据精度，完成环境温度测量仪的设计与制作，实现环境温度的精准采集、实时显示、阈值报警，测量仪结构精简、成本可控*

> **实施变更摘要（2026-10-10，V1.1）**——本版按最终实物修订，与 V1.0 的主要差异：
> 1. **搭建路线：全程面包板，免焊接**。放弃洞洞板 + 排母与立创 PCB 打样——操作简便、迭代快；团队成员焊接经验生疏，避免焊接返工拖期；验收不要求 PCB。
> 2. **模拟通道：取消 MCP6002 运放调理，LM35 直接采样进 PA4**（1→5V、3→GND、2→R9 100 Ω→PA4）。到货的 MCP6002 为 SOIC-8 贴片封装，无法直插面包板；直采链路更短、误差源与故障点更少。代价：**0 ℃ 以下无法测量**（单电源无偏置）。
> 3. **C3 100 nF 抗混叠电容未安装**（可选件，实测读数稳定；若出现抖动可加回 PA4↔GND）。
> 4. **单只 DS18B20**；蜂鸣器改 **3 针模块**（自带驱动，无 S8050）；按键 **3 个**（SET/＋/－）；**AT24C02 未安装**（阈值仅存 RAM，断电回 30.0 ℃）。
> 5. **供电与调试：USB 供电（5 V + CH340），ST-Link 仅接 SWDIO/SWCLK/GND**。
> 6. 固件按直采公式 `T = V / 0.01` 换算；DS18B20 5 点滑动平均、LM35 16 次采样平均；VREFINT 校正、软件标定与 EEPROM 存储未实施（列为后续优化）。

## 2. 方案论证（为什么这样选）

### 2.1 主控三条路线对比

| 路线                                                                                                                                                                                                                         | 代表                       | 优点        | 缺点                                               | 结论              |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | --------- | ------------------------------------------------ | --------------- |
| A：8 位                                                                                                                                                                                                                      | STC89C52 / STC12C5A60S2  | 资料最多、上手最快 | 无 12 位 ADC（LM35 需外挂 ADS1115）、无硬件 I²C 需软件模拟、精度上限低 | 否（与"32 系列"要求不符） |
| B：32 位国产                                                                                                                                                                                                                   | CH32V003 / CKS32F103C8T6 | 便宜        | 生态与教程少，ADC 一致性资料不足                               | 否（作为 B 计划备用）    |
| **C：STM32F103C8T6** | 通用 Blue Pill | 内置 12 位 ADC + 温度传感器 + VREFINT + 硬件 I²C/USART/TIM；**（同型号板 + Keil MDK + 标准外设库），单总线 DS18B20、OLED、AT24C01、ADC、TIM-PWM、串口例程可逐章直接复用**；实验室示波器/仿真器通用 | 引脚多、需理解时钟树；标准库需自己配置寄存器（教程已覆盖） | **采用** |                          |           |                                                  |                 |

**采用理由（写进报告）**：① 满足"32 系列"要求；② 片内 12 位 ADC 与 VREFINT 自检通道，使 LM35 通道无需外置 ADC，符合"结构精简、成本可控"；③ 团队正按（Keil MDK + 标准外设库）学习同一型号芯片，**开发路线零切换成本**，2 个月内可完成。

### 2.2 双传感器通道的必要性（本项目立论核心）

| 对比项  | DS18B20（数字）              | LM35（模拟）             |
| ---- | ------------------------ | -------------------- |
| 接口   | 1-Wire，占用 1 个 GPIO       | 需 ADC（本版直连，无调理）      |
| 分辨率  | 0.0625 ℃（12 位，可设 9～12 位） | 受 ADC 分辨率限制（约 0.08 ℃/LSB） |
| 精度   | ±0.5 ℃（−10～+85 ℃）        | ±0.5 ℃（+25 ℃ 典型），需标定 |
| 转换时间 | 12 位 750 ms              | 即时（可 1 kS/s）         |
| 优点   | 免标定、抗干扰、可多点总线            | 响应快、可高频采样、验证模拟链路设计能力 |
| 缺点   | 慢、假货多                    | 量程受单电源限制（0 ℃ 以下不可测） |

→ **两路互为校核 + 故障切换**，正好把"优化数据精度"做成有对比、有数据、有图表的结题亮点。

**外部实测佐证（开源调研 2026-09-02，详见附录 D）**：

* **精度目标可达成**：`Cyclohexi/STM32-Smart-Thermometer`（MIT）在同型号 F103C8T6 + SSD1306 上，仅用**两点线性校准**即实测残差 **RMS ≈ 0.5 ℃** → 本方案 M3 的 ±0.5 ℃ 不是拍脑袋指标。本版以 **16 次采样平均 + 5 点滑动平均**实现基础降噪（VREFINT 反算、64 次过采样与多点最小二乘标定列为后续优化），指标仍保守写 ±0.5 ℃，避免答辩时被单点数据反问。

* **响应时间必须量化**：`Santocoyo/Comparison-of-sensitivity-of-temperature-sensors-LM35-and-DS18B20`（MIT）用**空气 / 冷水 / 热水三种介质的阶跃对比**证明 LM35 明显快于 DS18B20 —— 这正是选题要求中"响应迟缓"痛点的实测形态。故新增 **M12 响应时间**指标（见 1.2）与阶跃测试步骤（见 6.1 步 10），并把"两通道 t63 对比曲线"作为报告核心图之一。

## 4. 硬件设计（到引脚、到电阻值）

### 4.1 主控最小系统 U1

* 直接用最小系统板：板上已含 STM32F103C8T6、8 MHz HSE、AMS1117-3.3、复位电路、BOOT0/BOOT1 跳线、板载 USB-TTL（CH340G，接 PA9/PA10）与 micro-USB。

* **上电前必查**：BOOT0 跳线接 GND（从 Flash 启动）。Blue Pill 常见"焊反 BOOT 排针导致无法启动"。

* **VDDA 处理**：板上 VDDA 与 VDD 已内部相连；额外在 VDDA 引脚附近加 **100 nF + 1 µF + 10 µF** 去耦（LM35 通道精度依赖它）。

* **PC13 心跳灯**：本版实际用 PC13 板载 LED 作 1 Hz 心跳指示，所用批次驱动正常；若遇驱动弱/闪烁异常，可改 PB0 外接 LED。

### 4.2 DS18B20 数字温度通道（1-Wire）

```
        3.3V ─────┬────── R1 4.7kΩ ──┐ (上拉，紧贴 DS18B20 端)
                  │                  │
   VDD(左)  ──────┘                  ├────── PA1 (GPIO 开漏/内部上拉)
   DQ (中)  ─────────────────────────┘        │
   GND(右)  ────── GND ───────────────────────┴──── GND
        │
   DS18B20 TO-92（字面朝自己，引脚从左至右：GND / DQ / VDD）
   ※ 若买模块版：模块上已有 4.7k 上拉，直接接 VCC/DQ/GND 三线
```

* **本版只装 1 只 DS18B20**（模块版，上拉在模块上）。驱动用 0xCC 跳过 ROM，仅支持单只；双探头冗余为后续扩展（需补 ROM 搜索/匹配）。

* 接线长度 ≤ 30 cm 用 4.7 kΩ；若探头延长到 1 m，上拉降到 **2.2 kΩ** 并用三芯线（VDD/GND/DQ），**严禁寄生供电**（VDD 悬空会导致 −7 ℃ 恒定读数）。

* 探头处加 **100 nF 到 GND**，长线串 **100 Ω**。

* **典型坑（写进报告的"调试记录"）**：

  1. 读到 `0x0550`（=85 ℃）→ 上电复位默认值，说明没做 Convert T，只读了暂存器；

  2. 读到 −7 ℃ / 恒定值 → 寄生供电或 VDD/GND 接反；

  3. 时序被中断打断 → 复位/写时隙必须**关中断 + 用 DWT 精确微秒延时**（教程 `Delay.c` 的 `Delay_us` 是按 72 MHz 标定的空循环，改优化等级或主频就会偏；且 SysTick 在 PRIMASK=1 时不计数 → 这是本项目最容易踩的坑）。

* **本版为阻塞式读取**：`StartConv` 后 `Delay_ms(760)` 再读暂存器（简单可靠，OLED 约 1 s 刷新一轮）；"非阻塞 + 期间刷新"列为后续优化。

* 每帧读 9 字节，做 **CRC8（多项式 x⁸+x⁵+x⁴+1，反射式 0x8C）** 校验，CRC 错则丢弃并计入错误率统计（报告可给"10 万帧 CRC 错误 0 次"的数据）。

### 4.3 LM35 直接采样通道（ADC1_IN4，本项目模拟通道）

**实际实施方案（V1.1）**：取消运放调理，LM35 输出经一只串联电阻直接进 ADC。

```
   LM35DZ（TO-92，平面朝自己、脚朝下：1 VCC / 2 OUT / 3 GND）
   1 ── 5V（USB 供电；LM35 需 4～30 V）
   3 ── GND
   2 ── R9 100 Ω ──┬── PA4（ADC1_IN4）
                   │
              （C3 100 nF 未装，可选）
```

* 换算：`T(℃) = V / 0.01`（10 mV/℃）；**0 ℃ 以下输出为负、单电源无法测量**，固件对负值按 0 处理。
* 量程：硬件 0～+100 ℃（ADC 0～1 V 段）；实际验收按 0～+80 ℃。
* 分辨率：3.3 V / 4095 ≈ **0.806 mV/LSB ≈ 0.08 ℃**；软件 **16 次采样平均**抑制噪声。
* 采样配置：ADC1_IN4，独立模式单次转换，**采样时间 239.5 cycles**（ADC 时钟 12 MHz，APB2/6）。
* 主要误差：LM35DZ 自身 ±0.5 ℃（25 ℃ 典型）、AMS1117 基准 ±1.5%（未做 VREFINT 校正）、面包板接触与走线干扰 → 结题以实测比对（冰水/室温/热水）为准。
* **为什么放弃运放（记录）**：原设计为 MCP6002 偏置放大（`Vout = 2·V_SEN + 0.4125 V`，可覆盖 −20～+135 ℃）。实际到货为 **SOIC-8 贴片封装**，无法直插面包板；且本版优先"操作简便、少一个故障点"，故改为直采。代价是失去负温段——M1 的 −10 ℃ 项实测不可达（测试手段也只有冰水/热水，产不出负温）。
* **备选方案（原设计，未实施，供后续 PCB/升级版参考）**：单级偏置同相放大，`Vout = 2.0·V_SEN + 0.4125 V`，`T = (Vout − 0.4125) / 0.02`。R3 15 k / R4 1 k 分压得 0.206 V 基准（U4A 跟随），R5 / R6 10 k 求和，U4B 增益 4（1 + R8 30 k / R7 10 k），R9 100 Ω + C3 100 nF 进 PA4。若后续换 PCB 或补直插运放，可恢复负温量程（接线见《B板模拟接线图》存档）。

### 4.4 显示模块 D1（SSD1306 I²C）

* 4 线：`VCC→3.3V`、`GND`、`SCL→PB6`、`SDA→PB7`。

* **总线方案：OLED 走教程的"软件模拟 I²C"驱动（PB6=SCL、PB7=SDA，GPIO 开漏/推挽 + 输入读）**。理由：① 教程 OLED 例程可直接复用；② STM32F103 硬件 I²C1 有已知 BUSY 位锁死 errata；③ 刷新量小，软 I²C 足够。AT24C02 本版未装。

* **I²C 上拉**：确认板上有 4.7～10 k 上拉；若无，PB6/PB7 各加 4.7 k 到 3.3 V（Blue Pill 多数批次无此上拉，**这是"屏幕不亮"的第一嫌疑**）。

* 地址：本版固定 **0x78（7 位 0x3C）**；0x3D 批次需改宏。

* 界面（128×64，分 4 行 + 状态栏）：

```
┌────────────────────────────┐
│ DS18B20:22.33C            │  ← 0.01 ℃
│ LM35:  22.3 C             │  ← 0.1 ℃
│ TH: 30.0 NORMAL           │  ← 阈值 + 状态（报警时 ALARM）
│ K1:SET K2:+ K3:-          │  ← 按键提示（设置时：SET TH: K2+ K3-）
└────────────────────────────┘
```

* 刷新策略：主循环每轮整屏刷新（约 1 Hz，无明显闪烁）；增量刷新列为后续优化。

* **若老师坚持"液晶显示"**：换 LCD1602A + PCF8574T（同为 I²C，总线不动，仅换驱动函数），显示 `T=25.43C  ALM:OFF` / `H:30.0 L: 5.0`。方案默认 OLED，理由：免对比度电位器调试、无字符偏位问题、省 1 小时调试时间。

### 4.6 报警电路（3 针蜂鸣器模块 + LED）

```
 PA6 (TIM3_CH1, 2 kHz PWM) ── IO  ┐
```

### 4.8 参数存储（AT24C02，本版未安装）

> **本版未实施**：未安装 AT24C02，固件亦未包含其驱动；阈值仅保存在 RAM，**断电重启恢复默认 30.0 ℃**（M8 记为"不适用"）。以下为预留设计，供后续升级参考。

* 与 OLED 共用同一条 I²C 总线（PB6/PB7，软件模拟），靠从机地址区分：OLED `0x3C`、AT24C02 `0x50`。

* 存储结构（40 字节）：`magic(2)=0x5A17 | ver(1) | k_x10000(4,float32) | b_x1000(4) | TH_H(2,int16×10) | TH_L(2) | 回差(1) | 亮度(1) | 单位(1) | 采样周期(1) | 保留(15) | CRC16(2)`

* 写入策略：**只在"确认"键或参数变化后写**，避免 750 ms 循环擦写（EEPROM 寿命 100 万次，但仍应规范）。

* 三条防呆规范（吸收自 `Cyclohexi/STM32-Smart-Thermometer`，MIT，见附录 D.1）——把"能存"做成"存不坏"，答辩可直接作为软件工程规范讲：

  1. **写前合理性校验**：任一参数越界即拒绝写入并在 OLED 提示 `ERR`（k 限定 0.80～1.25、b 限定 ±5.0 ℃、TH-H/TH-L 限定 −20.0～+135.0 且强制 TH-H > TH-L + 回差）→ 防止误操作把标定系数写成垃圾值后"再也读不回来"。

  2. **3 s 防抖**：两次 EEPROM 写入的最小间隔 3 s（用 TIM2 时基记时间戳），期间再次按"确认"只更新 RAM 不擦写 → 避免连按导致同一页反复擦写。

  3. **上电三重判定**：`magic` + `ver` + `CRC16` **任一不符**即用默认参数表（附录 B）覆盖 RAM 并回写一次 EEPROM，同时在串口日志记一条 `EEPROM_REINIT` → 保证"参数丢不了、板子换得不怕"。

### 4.11 PCB / 装配要点（本版未实施，留作后续）

> **本版为面包板整机、免焊接**：未投板、未做洞洞板；以下要点供后续 PCB 版参考（原计划的运放、AT24C02 等需按 4.3/4.8 的备注调整）。

4. 8 MHz 晶振走线尽量短、包地、下方不掏地（用板载则免）。

5. 全部传感器/显示/按键用 **排针 + 杜邦线引出**，坏了能换（学生项目返修率主要在这里）。

6. 板上预留 **2 个测试焊盘**（VDDA、ADC_IN4）+ 1 个 UART 排针 → 结题答辩现场可测。

7. 装配顺序：先焊电源 → 测 3.3 V → 焊主控+排针 → 烧录心跳灯 → 逐模块插拔调试。**不要一次焊满**。

### 5.3 主循环调度（前后台）

本版未使用 TIM2 时间片调度器与状态机，采用**主循环顺序执行**（前后台结构），一轮约 0.8 s：

| 步骤 | 内容 | 说明 |
| --- | --- | --- |
| 1 | DS18B20 StartConv | 启动 12 位转换 |
| 2 | Key_GetNum() | 等待转换期间扫描按键（20 ms 消抖） |
| 3 | Delay_ms(760) | 等转换完成 |
| 4 | DS18B20 读数 + CRC + 5 点滑动平均 | 失败则丢弃并打印 CRC error |
| 5 | LM35_GetTemp() | ADC 16 次平均 → `T = V/0.01`（负值按 0） |
| 6 | Alarm_Update(DS 滤波值, 阈值) | 0.5 ℃ 回差 |
| 7 | Display_Update() | OLED 四行刷新 |
| 8 | printf CSV 一行 | 约 1 Hz |
| 9 | PC13 心跳翻转 | 主循环存活指示 |

### 5.4 数据精度处理（报告"数据精度优化"章节正文）

**本版已实现**：

1. **DS18B20：5 点滑动平均**（上电用首次数值预填充缓冲，避免均值偏小）。

2. **DS18B20：CRC8 校验**，校验失败丢弃本帧（串口记 `CRC error`）。

3. **LM35：16 次 ADC 采样平均**（单次采样时间 239.5 cycles）。

4. **报警回差 0.5 ℃**，避免阈值附近抖动连响。

5. 显示分辨率：DS18B20 0.01 ℃、LM35 0.1 ℃。

**列为后续优化（未实施）**：中值滤波、一阶 IIR、64 次过采样、VREFINT 反算 VDDA、两点/最小二乘软件标定（需 AT24C02 或 Flash 存储系数）、双通道一致性判据与故障切换。原设计思路保留在本文档 V1.0 与附录 D 中，作为答辩"改进方向"素材。

### 5.5 关键代码片段（实际实现）

```c
/* LM35 直采：16 次采样平均 + 10 mV/℃ 换算（负值按 0 处理） */
static float LM35_GetTemp(void)
{
    uint32_t sum = 0;
    for (uint8_t i = 0; i < 16; i++) sum += LM35_ReadRaw();  /* ADC1_IN4, 239.5 cycles */
    float vin = (float)sum / 16.0f * 3.3f / 4095.0f;
    float t = vin / 0.010f;                                  /* 10 mV/℃ */
    return (t < 0.0f) ? 0.0f : t;
}

/* 主循环一轮（约 0.8 s）：采样→滤波→报警→显示→串口→心跳 */
DS18B20_StartConv();
key = Key_GetNum();                    /* 等待转换期间扫键 */
Delay_ms(760);
if (DS18B20_ReadTemp(&raw)) tempFiltered = Filter_Update(raw);
lm35Temp = LM35_GetTemp();
Alarm_Update(tempFiltered, threshold); /* 0.5 ℃ 回差 */
Display_Update(tempFiltered);
printf("%d,DS=%d.%02dC,LM=%d.%dC,TH=%d.%dC,%s\r\n", ...);
```

### D.3 明确不采用（避免踩坑）

* **ARM-software/CMSIS-DSP**（1076★，Apache-2.0）：均值/中值/FIR/IIR 的标准实现。算法正确，但为一个 250 行的滤波器引入整个 DSP 库（编译配置、内存段、依赖）不值得。**结题报告里改为引用它来论证"本方案滤波链与业界标准实现一致"**，比使用它更能加分。

* **任何 HAL/CubeMX 版温度计数显项目**（含江协教程的第三方 HAL 移植版，如 OceanCing/I2C_OLED-HAL_Version、Tracker647/JiangKeDaHAL）：与本方案不同库，**只当原理参考，禁止复制函数**（见 5.0 注意事项）。

* **FreeRTOS / 触摸按键 / WiFi 上传**类扩展：与 2 个月工期冲突，见 R8、R11。

### D.4 许可与学术规范（写进报告"参考资料"的规矩）

1. **无 LICENSE ≠ 可自由使用**：GitHub 仓库默认"保留所有权利"，把无许可代码整段拷进提交物属学术规范风险 → 一律只读思路。

2. **MIT / Apache-2.0 可用**，但必须①保留原版权声明，②在报告"参考资料"写明**具体文件与作者**，③在源码文件头注明出处与改动点。

3. **GPL 的 PC 端工具（serialplot）不影响固件许可**（独立进程、无代码链接）；但绝不能把 GPL 代码拷进单片机工程。

4. 报告里主动写一节 **"自研 / 复用清单"**：自研＝LM35 直采链路与整机接线、采集/显示/报警业务层、面包板结构与调试记录；复用＝江协教程底层驱动 + 附录 D.1 的 MIT 部件。**评审老师最反感"整份网抄"，最认可"引用规范 + 自研比例明确"。**
